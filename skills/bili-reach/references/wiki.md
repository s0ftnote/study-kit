# 入库交接

已有可读材料，且用户要求“进知识库 / 跨来源关联 / 合并笔记”时加载。将现有原稿、截图或笔记交给通用入库流程；用户还需要课程笔记时走[笔记整理](<course-materials.md>)。

## 交接流程

1. **整理材料入口。** 读取来源清单与已有待审稿，按下表列出本次相关材料和证据。**完成标准：**接收方可独立定位来源、采集版本、片段或帧，并了解已核对范围与缺项。
2. **交给接收方。** 环境有适用的通用入库 skill 时加载并交接；否则交付材料包和待审建议。实际写入前确认目标库、组织规则与授权范围。**完成标准：**材料已交给明确的接收方，或已交付可使用的本地材料包。
3. **报告结果。** 列出已交付材料、待核对项和接收方确认的写入结果；尚无写入结果时标记“待入库”。**完成标准：**材料位置和实际入库状态可查。

## 交接的最少信息

| 项目 | 内容 |
| --- | --- |
| 来源身份 | BV、cid、P、标题、规范 URL、字幕/ASR 或仅截图的来源类型、本次 runId；用户材料缺项明确未知。 |
| 证据入口 | 材料目录与清单、原稿及截图、已有待审资料页；绝对路径只用于当前机器定位，稳定引用保留来源身份和 revision。 |
| 片段依据 | 相关主题/例题的实际起止时间，或已查看帧的秒数、所选 P 的回链与证据位置；完整题目尚未确认时仅交候选位置，不由单帧推断整段。 |
| 疑点与范围 | 已读范围、画面核对状态、未确认的数字/公式/条件、缺失材料，以及 AI 补充与老师原讲的区分。 |
| 用户意图 | 本次是仅备料、拟关联/新建，还是按既定规则申请写入；目标库和现有笔记仅在用户或接收方实际确认后填写。 |

## 接收方的工作

围绕本次材料查询已有条目，完成跨来源去重、概念映射、题目整理和关联。保留片段级出处、来源冲突与待审项，提供变更预览，并按确认的规则与授权写入。
