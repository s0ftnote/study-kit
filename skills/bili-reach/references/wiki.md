# 入库交接

仅在已有可读材料，并且用户要求“进知识库 / 跨来源关联 / 合并笔记”时加载。单纯取稿、截图或来源内整理不触发查重关联。获取失败先处理获取问题，不用标题或常识补写课程正文。

本文件负责把来源材料交给**通用知识库入库职责**，不在 B站 skill 内另建一套知识组织或直接改主库。来源内资料页按需走[来源内整理](<course-materials.md>)；已经完成的材料直接复用。

## 交接流程

1. **列交接材料。** 读取来源清单与已有待审稿，按下表交付实际材料和本次相关证据，不另建空栏目。原稿或截图可直接交接，无需先补完整课资料页，也不重复采集。**完成标准：**下游不读聊天就知道材料来自哪一 P、哪些片段或帧、哪次采集及哪些条件未知；仅截图明确没有 transcript，未读正文不被概括。
2. **确认接收方。** 若环境有适用的通用入库 skill，加载并交给它；否则交付材料包和待审建议，说明独立入库 skill 尚未提供。只有实际写入时才确认目标 Wiki、组织规则与授权范围；仅准备材料不要求用户先配置笔记软件。**完成标准：**接收方和权限真实明确，或已停在可使用的本地交接材料；不编造工具、库目录或已经入库的结果。
3. **汇报边界。** 区分本 skill 完成的采集/来源内整理与入库侧的查重、概念映射、题目整理和实际写入。接收方没有返回可核实的结果，就标记“尚未确认入库”。**完成标准：**能指出已交付材料、未核对项及实际入库状态；没有越权写主库或修改个人学习记录。

## 交接的最少信息

| 项目 | 内容 |
| --- | --- |
| 来源身份 | BV、cid、P、标题、规范 URL、字幕/ASR 或仅截图的来源类型、本次 runId；用户材料缺项明确未知。 |
| 证据入口 | 材料目录与清单、原稿及截图、已有待审资料页；绝对路径只用于当前机器定位，稳定引用保留来源身份和 revision。 |
| 片段依据 | 相关主题/例题的实际起止时间，或已查看帧的秒数、所选 P 的回链与证据位置；完整题目尚未确认时仅交候选位置，不由单帧推断整段。 |
| 疑点与范围 | 已读范围、画面核对状态、未确认的数字/公式/条件、缺失材料，以及 AI 补充与老师原讲的区分。 |
| 用户意图 | 本次是仅备料、拟关联/新建，还是按既定规则申请写入；目标库和现有笔记仅在用户或接收方实际确认后填写。 |

## 接收方需要守住的边界

跨课程、教材和试卷的去重、同义词处理、概念/方法笔记、正式题目记录及知识关系图，只在本入库分支交给接收方统一处理。围绕本次待入库内容查相关已有条目，不要求采集或资料整理先扫全库；保留片段级出处，变更可预览，按已明确的规则与授权写入，保留来源冲突与待审项。

孩子的原始作答、错题和复测证据属于独立学习流程。课程入库不增加掌握度，教师易错提示不变成个人错因记录。这里不初始化 Lorekeeper 或 `.lore`，也不凭“需要入库”自动创建个人知识库。
