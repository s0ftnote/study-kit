# 需求与分工规划（待确认）

本文保留需求分工与后续方向，不表示所有规划均已实现。当前安装与使用见 [README](../README.md)，产物与状态以[素材数据契约](../skills/bili-reach/references/data-contract.md)为准。

## 1. 目标：让网课成为可回查、可复用的学习资料

不是把视频变成一篇孤立摘要，也不是导入后就认为孩子掌握了内容。

希望最终支持：孩子做题暴露一个问题时，可以从已有知识点找到合适的网课讲解片段、原题或板书，回看后再安排练习与复测。B 站工具解决其中的资料获取与定位；知识库负责跨来源组织；学习记录负责证明孩子当前会不会。

## 2. 之前五项能力全部保留

| 已规划能力 | 保留后的要求 |
| --- | --- |
| 识别视频和指定分 P | 区分课程、视频与分 P，展示所选标题、cid、时长，越界明确失败 |
| 获取字幕或调用 ASR | 优先平台字幕，明确无字幕才本地转写；登录、风控和请求失败单独处理 |
| 保存完整时间轴与来源 | 保存原稿、来源身份、分段时间、处理方式；报告缺失与未核实项，不把格式有效当准确率保证 |
| 按时间点抓题目、板书 | 用户指定或 agent 根据原稿判断需要时取图；保留时间点与原片回链，截图不等于已理解图像 |
| 返回路径与处理状态 | 人能读、程序能接；明确成功、部分完成、失败、需登录、需准备工具、缓存复用与待核对状态 |

“部分完成”是拟新增的细分状态：例如文字已取得而某张截图失败，需要准确报告各项状态；不把整体任务标为全部成功，也不破坏旧成功资料。现有实现如何兼容要在继续开发前更新契约与测试。

## 3. 一个入口，职责分开

```text
B 站课程
   ↓ bili-reach：采集与来源内整理
课程资料包：原稿、时间轴、画面证据、资料页、片段导航
   ↓ 知识库入库 skill：跨来源组织
来源笔记、概念/方法、题目、已有笔记关联、知识地图
   ↓ 练习与学习记录流程（另一个职责）
原始作答、错因假设、针对性回看与练习、延迟复测
```

用户仍可只说一次“把这节课整理进知识库”。调度它的 agent 可以顺序调用两项职责；不要求用户手动分两次操作。两个职责不必是两个后台服务，也不引入新的常驻进程。

### A. bili-reach：我从这份来源里实际取得了什么

负责 B 站访问、媒体处理与课程内部导航。只围绕本次视频及明确选择的分 P 说话，不需要知道整个知识库如何命名和分类。

- 原始材料：平台字幕或本地 ASR 原始输出，必要的音视频/图片及完整可用时间轴。
- 来源身份：原 URL、BV、cid、分 P、标题、作者、时长、采集日期、字幕或 ASR 来源与配置。
- 来源内整理：按实际讲解划段、写课程目录、标出定义/方法/例题/板书/教师易错提示出现在哪些时间段。
- 质量提示：字幕疑点、无法确认的数字或符号、画面未核对、缺失范围、处理失败原因。
- 导航回链：每段与每张图能定位回原片；引用原稿与图片，而非只留下概括。

程序负责确定性的下载、时间轴、路径与状态；调用它的 agent 负责有依据的分段和描述。工具本身不绑定 LLM、不内置另一套总结模型，也不因此要求额外模型账号。

### B. 知识库入库 skill：这些材料与已有知识有什么关系

这是面向书籍、试卷、课程等来源的通用职责，不能写死为“B 站笔记导入器”。

- 查询已有来源与知识点，决定复用、关联、新建还是暂不入库。
- 将课程内部的概念用语映射到库中的统一名称，处理同义词与重复内容。
- 将原课解释、使用条件、解题方法与例题整理成待审笔记，并保留片段级来源。
- 区分讲师原讲、AI归纳/补充和待核实内容；遇到来源冲突保留差异，不能静默合并。
- 将能完整确认的例题整理为题目记录，关联原题、讲解、方法与答案；条件/图像不完整时保留为候选而非补造题目。
- 建立跨课、跨书的联系与局部知识地图；生成变更预览，按用户认可的入库规则写入。

它不重新下载视频、不另做一套 ASR，也不把 AI 整理稿覆盖到原稿。

### C. 学习记录：孩子实际做过什么

课程里老师说的“常见错误”属于教学内容，不是这个孩子的错因证据。

听过课、看懂解析、独立做对、换题做对与延迟复测通过分别记录。只有明确的学习事件与作答证据才进入个人学习记录；采集或入库不能自动增加掌握度，不能覆盖原始作答。

## 4. 我们希望得到的形式

| 产物 | 所属职责 | 定位 |
| --- | --- | --- |
| 原稿、SRT/JSON、必要附件 | bili-reach | 原始证据与通用接口，保留可追溯性 |
| 课程资料页（Markdown） | bili-reach 的来源内整理 | 人的入口：来源、讲解顺序、时间段、例题/板书位置、疑点；不是全库知识笔记 |
| 片段导航和候选例题位置 | bili-reach | 供人或后续 skill 直接找到相应材料；没有看到完整题目时只标位置 |
| 概念/方法笔记、正式题目记录 | 知识库入库 | 与已有库统一组织，不为每节课复制一遍相同概念 |
| 来源间的关联与知识地图 | 知识库入库 | 从经过整理的内容和关系派生，可随库更新 |
| 作答、错因假设与复测记录 | 学习记录流程 | 独立于课程资料和知识内容 |

默认以 Markdown、JSON 与图片等可迁移文件为主。JSON负责结构化交换，Markdown负责阅读；导出格式不是另一份需要独立维护的事实来源。资料包可放进 Obsidian 的来源/待审区域，也能被其他系统读取；核心不依赖 Obsidian、DSH 或任何原项目。

## 5. 思维导图放在哪里

不砍掉图的可能性，但不默认强制每节课画一张图。

1. **课程结构图（来源内）**：展示本节课的讲解顺序及片段位置，可由 bili-reach 的课程目录按需生成；不能把讲解先后自动当成知识前置依赖。
2. **知识关系图（跨来源）**：展示概念、方法、前置关系与代表题，归知识库入库侧；关系需有依据，推断的关系标记为候选。
3. **个人薄弱点视图**：基于作答和复测证据，归学习记录侧；不能从“视频里讲过”推出“孩子已经掌握”。

三者不能混成一张没有证据边界的大图。图是笔记与关系的视图，文本/结构化记录仍可独立阅读和恢复。具体 Mermaid、Obsidian Canvas 或其他格式在实际需要时决定，不先绑定格式或额外插件。

## 6. 在原五项基础上建议增加的内容

### 本轮应纳入设计

- **来源资料包与课程资料页**：不仅返回几个散文件，让下游知道从哪里读起。
- **可检索的片段导航**：至少有段落主题、起止时间、回链与证据位置，之后能回答“这一点在哪里讲过”。
- **例题/板书位置标记**：先定位证据，完整题目和解法整理交入库侧。
- **质量与完整性报告**：采集状态、正文覆盖、疑点与图片核对状态分开；诚实表示部分完成。
- **可继续补材料**：先取得文字，读到某段需要板书时再抓图；用新版本或独立补充任务保留旧文件，避免仅补图就不必要地重做 ASR。
- **明确的交接约定**：下游依据来源标识、时间段和证据路径读取资料，不依赖某次聊天上下文。

### 留好扩展口，不都挤进第一版

- 多分 P 的选集清单、批量队列、可恢复的进度。
- 按教学段落智能选帧、局部转写重核、字幕和画面对照。
- 来源内的课程结构图、不同知识库格式的导出。
- 其他本地 ASR 引擎；默认仍不静默启用云服务。

这些不是删功能，而是区分“已有五项的可靠性要求”“本轮新增的资料价值”和“后续可选增强”。自动解题、自动判定孩子掌握程度与自动推荐整套训练计划，不属于这个采集工具的职责。

## 7. 实施顺序与验收

1. **确认边界。** 先确认五项保留、资料包形态及入库职责，再修改本地原型。完成标准：每项产物有唯一责任方，新增设计与现状差异有清单。
2. **采集底座。** 验证指定分 P、字幕优先、明确无字幕才本地 ASR、时间轴和来源、指定截图、失败不假报成功与防覆盖。完成标准：离线测试齐全，经授权的真实视频能回查到正确片段；未授权则标为待实网验收。
3. **来源内整理。** 用一节代表课程验证资料页、分段、例题定位和疑点标注。完成标准：不读整段聊天也能找到相关讲解，摘要有时间证据，不补造原题。
4. **入库交接。** 在独立测试库试接通用入库职责。完成标准：先查已有笔记、变更可预览、来源回链有效、重复导入不生重复概念、不改个人掌握状态。
5. **再扩展。** 根据实际使用瓶颈加入批量、图形或更多模型；不以输出文件数、摘要长度、图节点数作为学习效果指标。

代码和模板可以公开，课程材料、登录态、孩子作答与私有库不进入公开仓库。规划确认前不推送原型，不安装当前 DSH profile。
