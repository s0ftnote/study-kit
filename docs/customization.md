# 定制与上游比较

面向维护者：新增 ASR 后端、调整截图策略或评估上游变动时使用。产物字段、状态、来源标识和 revision 语义以 [数据契约](<../skills/bili-reach/references/data-contract.md>) 为准；这里不另建 schema。

## 本地配置，不改安全默认值

取稿默认允许本地 ASR，但只有确认无平台字幕才进入它；已有字幕不要求模型。独立 `frames` 不请求字幕、不做 ASR，也不要求模型。缺本次所需工具/模型返回 `NEED_SETUP`，下载前停止，由用户准备，不自动安装或下载。Node 的零运行时 npm 依赖不表示机器已有 FFmpeg、whisper.cpp 或模型；用 `doctor` 逐项检查 `available`，不是只看 `ok: true`。whisper 用 `--help` 兼容探测，`available: null` 是探测不确定，不是未安装。

将个人设置放在项目外的私有 JSON，用 `--config '/私有目录/bili-reach.json'` 引用。从 [非私有配置模板](<../skills/bili-reach/assets/config.example.json>) 选择需要的字段；配置键使用 CLI 等价的 camelCase。cookie 只通过 `cookieFile` 指向私有文件，不把 cookie 字符串写入 JSON、命令或仓库。分享排错信息时也去掉私有路径和材料。

媒体保留用布尔配置 `keepMedia`（默认 `false`），CLI 对应开关 `--keep-media`。默认只清理本次自建目录的中间音视频、WAV 和重复 Whisper JSON；`raw/asr.json`、字幕原稿与 PNG 长期保留。设为 `true` 时保留中间媒体并全量哈希；不扫描、清理旧 run 或用户资料。新增后端也须遵守此边界，失败时尽力清理本次大媒体，不能把清理错误伪装成采集成功。

本项目默认无云服务。换模型或添加术语表只是识别策略，不证明中文数学准确率；公式、数字、符号与原题条件仍需对照实际音频/板书核对。需要音视频供人工复核时，先明确保留需求；默认清理不等于已经核对。

## 加一个 ASR 后端

1. **读边界。** 先读数据契约，再定位当前媒体实现与采集编排的调用点。平台层继续只报告字幕状态；编排只在“明确无字幕”后调用后端。**完成标准：**写清后端输入、产物如何映射现有契约，以及错误如何保留为正确的下一动作；登录、风控、限流和网络失败不进入 ASR。
2. **实现本地适配。** 把模型/可执行路径作为显式配置，外部进程使用参数数组而非 shell 拼接；下载、临时目录、超时与资源限制沿用安全边界。先保存原始 ASR JSON，再校验和归一化时间段；中间文件按 `keepMedia` 保留或清理，来源引擎、模型标识和语言可追溯。**完成标准：**有效结果符合契约，无效时间线或空结果明确失败；原始证据保留，半成品不发布为成功 revision。
3. **验证兼容。** 使用虚构离线 fixture、替身进程与注入网络覆盖正常结果、缺项、非零退出、超时、坏 JSON、空正文和非法时间段；验证默认清理、显式保留及保留文件完整性，失败不改变旧缓存和人工文件。**完成标准：**新增后端与原字幕路径都有测试，独立截图不被带入 ASR，旧 revision 仍可读取且未被扫描清理。
4. **接入用户入口。** 仅在确需暴露配置时修改 CLI 和 DSH wrapper，二者继续复用采集编排；同步配置示例、契约中真实变更的部分和 skill 的分支。**完成标准：**CLI 与 wrapper 的同输入得到相同语义，私有路径/凭据不会泄漏；默认仍无需云服务。

若要支持云 ASR，把它作为另一个**显式选择**的后端设计：先征得用户对音频上传、提供方、费用和凭据保存方式的同意，再实现与测试。云端不能作为本地失败后的静默回退，也不能以添加后端为由上传现有课程材料。

## 独立截图与取稿附图

CLI 有 `doctor`、`inspect`、`collect`、`frames` 四个 action。核心仍复用 `collect` 编排，以 `kind: 'frames'` 或 `kind: 'transcript'` 选择任务；只截图走前者，取稿及取稿附图走后者，wrapper 不另写采集逻辑。

- 独立取图：`frames '<URL>' --part N --frames 30,90 --output DIR`，完全跳过字幕与 ASR，不检查模型。
- 同时取稿：`collect '<URL>' --part N --frames 30,90 --output DIR`，保留字幕优先和仅明确无字幕才 ASR 的原逻辑。

时间点须处于所选 P 的有效时长内，单次最多 12 个；截图不自动 OCR、理解板书或扫描整门课。策略变更复用安全下载与进程边界，独立截图不能要求 transcript，也不能由几帧概括整课。

两类成功指针分别为 `latest.frames.json` 与 `latest.json`，互不覆盖；缺所需截图或缓存未保留请求媒体时，确认后用 `--refresh` 新建版本。独立补图不重做转写，失败不以旧图假装完成，不补写旧 revision。其余产物、哈希和缓存细节查[数据契约](<../skills/bili-reach/references/data-contract.md>)。

## 如何跟上游比较

比较是只读评估，不是直接拉取并覆盖本项目：

1. **固定基线。** 从项目来源说明及源码归属注记找到上游，记录双方实际版本/commit、相关文件与许可证。没有固定版本或无法核实时，标记“未核实”，不要称已追平。**完成标准：**比较对象和授权边界明确。
2. **按能力比较。** 对照 URL/分 P 解析、字幕状态、媒体选择、ASR 接口、截图、凭据传递、缓存和发布；区分 API 事实、上游实现选择与本项目约定。**完成标准：**每个相关差异都有证据位置，以及保留/采纳/暂缓的理由。
3. **先做离线回归。** 用新造的 fixture 表达准备采纳的行为，不复制上游 cookie、真实课程材料或孩子数据；优先修复状态误分类与安全差异。**完成标准：**差异能在离线测试里复现，修复后仍满足本项目契约。
4. **单独申请联网验证。** 确实需要 B站实网测试时，先取得用户对具体范围的明确同意；只访问同意的 BV/P/请求，风控或限流立即停下，不重试绕过。**完成标准：**记录实际验证范围和未验证部分；报告与仓库均不含凭据或材料正文。

比较结论应说明哪些改动只是上游差异，哪些是本项目有意保留的约束。文档更新、离线测试通过、能运行 `doctor` 都不能替代真实平台验证，也不能证明 DSH 工具已装进当前 profile。
